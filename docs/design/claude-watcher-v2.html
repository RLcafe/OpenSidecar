What's new on the card

  • Car gauges with pace. The 5-hour limit is a tank gauge with a needle, a pace tick (how much of the window has passed) and a hatched projection: "on pace for 92%" turns Amber when you'll hit the limit before it resets. The week is seven laps, one per day, with a flag at the reset.
  • A rev counter. Tokens per minute right now, with a redline and the last hour beside it, so a heavy thread shows the moment it starts.
  • A pit stop strip. The thread that needs you gets its own row under the meters with what it wants ("Wants to use Bash: npm run build") and a Go button.
  • A garage ledger. Each project is a garage with its threads as race cars underneath: state chip, title, where it runs, age, tokens, ≈ $, model mix and lines added and removed.
  • A 5-hour timeline. One lane per project in 10-minute bins, so you see which project ate the window.
  • Four facts. Today's tokens and ≈ $, cache hit rate, tool calls (denied and asked), and lines changed.

Pixel pit art: what to ask an image model

Don't ask for finished animations. Image models can't keep a car identical across frames. Ask instead for a rig: car bodies with empty wheel arches, wheels on their own with four spin frames, and the lights and smoke as separate layers. The bodies use four fixed greys, so the app swaps them for each project's colour (and Slate, Warm and every accent keep working). The app then does the motion itself, frame by frame, with hard pixels: wheels turning, hazards blinking, smoke, cars rolling into the garage.

How to run it

  1. Use a model that can output a transparent PNG (for example GPT Image with transparent background, or Ideogram/Recraft with background removal). If yours can't, keep the magenta #FF00FF background in the prompts; I'll key it out.
  2. Run prompt 1 until you like the cars and the garage. Keep that image and attach it as the reference for every other prompt ("match these exactly").
  3. Run prompts 2 to 6 at 2048 × 2048 (or the largest square it offers); 7 is optional. Regenerate any sheet where parts touch, or where the pixels are blurry instead of crisp squares. I'll snap everything to a clean pixel grid and make the small sizes.
  4. Save them in Widget screen\assets\pit\source\ with the names shown on each prompt, then tell me. I'll cut, key, tint and wire them into both apps.

Rules every prompt already includes

  • Detailed pixel art with realistic proportions: crisp square pixels, no blur, no smooth gradients, a 1-pixel outline.
  • No faces. Status comes from the wheels, lights, smoke and how the car moves.
  • Original cars: no real makers or models, racing numbers, sponsor decals or text.
  • Exact side view, facing left, same scale and baseline, light from the top left.
  • Bodies in four fixed greys with empty wheel arches, so the app recolours them and spins the wheels separately.
  • Wide gaps between parts so they cut out cleanly.

Pixel animation steps at 6 to 24 frames a second instead of smooth tweening, which suits the style and is cheap. Quiet mode keeps only the state changes (no loops), and every loop stops while the card is hidden, so it still costs nothing during games.

One thing to confirm

The app's rules say "no images for icons", and the cars are drawn in code today. Using generated pixel art means shipping a small set of PNGs (about 80 parts, well under 1 MB, scaled up by whole numbers so the pixels stay sharp on the touchscreen and the phone). Your request covers that, and I'll record it as a decision. The layout doesn't depend on the art, so I can build it now with drawn stand-ins and swap in your images when they're ready.
