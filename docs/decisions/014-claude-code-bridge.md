# 014 — The Claude Code bridge: hooks, the status line and a read-only usage check

Ali asked (1 Nov 2026) for a widget that shows the Claude Code sessions on this PC, lights up when one is waiting on him, counts usage per project and per session, and shows his plan's limits (his Claude subscription, not API credits). The design is in [docs/design/claude-watcher.md](../design/claude-watcher.md).

## Decision

- **A small console exe, `ClaudeHook.exe`, is the bridge.** Claude Code runs it for its hooks (`ClaudeHook.exe hook`) and its status line (`ClaudeHook.exe statusline`) with JSON on stdin. It writes one file per session (`claude\sessions\<id>.json`) and the plan limits (`claude\limits.json`) into the folder it sits in, atomically, with a named mutex per session so concurrent hooks don't lose each other's change. It never blocks, always exits 0 and swallows every error, so a broken widget can't break Claude Code. It's built by `scripts\build.ps1` with the Framework's `csc.exe` from `hook\ClaudeHook.cs` and the shared, WPF-free files in `src\integrations\Claude\` (`ClaudeJson`, `ClaudeBridge`, `ClaudeProcesses`), ships next to `WidgetScreen.exe` in releases and in the setup exe, and Connect copies it to `%LOCALAPPDATA%\WidgetScreen\claude\ClaudeHook.exe` so Claude Code's settings survive new release folders.
- **The hooks give the states**: SessionStart (Ready), UserPromptSubmit and PostToolUse (Working), Notification for `permission_prompt|elicitation_dialog` (Needs you, with its message), Stop (Done), SessionEnd (gone). The hook also walks up from its own process to the Claude Code process (`claude.exe` or `node.exe`) and the first ancestor with a window; the dashboard drops a session whose Claude Code has gone, or that has been quiet for 12 hours, and a tap on a session brings that window forward.
- **The status line gives the plan limits.** For Pro and Max logins Claude Code's status-line JSON carries `rate_limits` (five-hour and seven-day, percentage and reset time; seconds since 1970 per the docs, an ISO time also parsed). Connect sets the status line to the bridge; a status line Ali already had is saved in `claude\previous-statusline.json`, and the bridge runs it (through Git Bash when it can, like Claude Code) with the same input and prints its output unchanged, so it keeps showing. Without one, the bridge prints `5h 23% · week 41% · ctx 8%`.
- **The read-only usage check fills the gaps** (Ali approved it, 1 Nov 2026, on the condition that it uses no credits): `GET https://api.anthropic.com/api/oauth/usage` with Claude Code's own sign-in token from `.credentials.json` and `anthropic-beta: oauth-2025-04-20`, every 5 minutes while the app runs with the Claude card on a page (his later change). The answer is undocumented and parsed defensively. The token goes only to that host over HTTPS (through `PreferIPv4Handler`), is read per request and dropped, never logged, stored, sent to the phone, or refreshed (refreshing would rotate Claude Code's own sign-in). Any problem silences the check for an hour. Settings → Claude can turn it off.
- **Usage comes from Claude Code's own logs**: `projects\<folder>\<session>.jsonl` under the Claude folder (`CLAUDE_CONFIG_DIR` honoured), each reply counted once by `message.id` + `requestId`, the four token counts added, and each session counted under the folder it started in. Files are read incrementally (only appended bytes, only files changed within 8 days) off the UI thread every 10 s (30 in Quiet mode), only while the card is on the page shown.
- **Connect and Disconnect edit `settings.json` surgically**: a backup first (`settings.json.widgetscreen-backup`), Widget Screen's hook entries appended to each event's array (never replacing another hook), the status line set, keys kept in their order, numbers and strings as written, and the file rewritten with Claude Code's two-space indentation; Disconnect removes exactly the entries whose command runs `ClaudeHook.exe` and puts the earlier status line back. A `settings.json` that isn't valid JSON is never touched. Only Ali's tap on Connect or Disconnect runs this against the real folder; the checks run it in temporary folders.
- **The phone** gets a `claude` section (sessions, limits, usage per period, never the token), two small fields in every answer for its header pill (`claudeNeeds`, `claudePage`), and one new command, `claude.focus`, which brings a session's window forward on the PC. Nothing else on the link changed. Android has no hooks or logs of its own: the phone is a remote, so it shows the PC's Claude Code.

## Rationale

- Hooks and the status line are Claude Code's own, documented ways to tell another program what a session is doing; nothing has to scrape a terminal or watch processes.
- A separate exe keeps Claude Code independent of the dashboard: the files are there whether or not Widget Screen is running, and the dashboard reads them when it starts.
- The status line is the one documented place the plan limits appear, and it costs nothing; the usage check keeps the meters current when no session is running, without spending credits.

## Tradeoffs

- **Claude Code starts a process per hook event** (one per tool call while working). It's a small .NET Framework console exe, async in Claude Code, and it skips rewriting a session's file for repeated Working events within a minute.
- **The usage endpoint is undocumented** and may change or disappear; the card then keeps the status line's numbers. Logged-out and API-key sessions never get plan limits, and the card says so.
- **Sessions killed without SessionEnd** disappear when their Claude Code process is gone (checked every 5 s while the card is on a page) or after 12 quiet hours when the process couldn't be identified.
- **Bringing a window forward** is best effort: Windows only lets the foreground app move the foreground, so the dashboard briefly joins the foreground thread's input and, failing that, taps Alt. If it still refuses, the window flashes on the taskbar and the dashboard says so.
- **Uninstalling** Widget Screen doesn't disconnect Claude Code; disconnecting first avoids a missing-hook error in Claude Code.
